## 第 0 页 封面

页面 ID cover。
建议时长 0.5 分钟。
论文出处 标题与摘要，[arXiv:2608.07645](https://arxiv.org/html/2608.07645v1)。

口播

大家好，我今天介绍孟德尔-哥德尔机，简称 MGM。
这项工作研究 coding agent 如何递归地改写自身源码来变得更强。
我们的做法是把档案库里已经积累的比较证据引入自主修改环节。
工作由电子科技大学、慕尼黑大学与慕尼黑机器学习中心共同完成，代码与论文均已公开。

转场

先交代这条研究线的来历，再说明我们改动了哪一环。

## 第 1 页 coding agent 走向自改进闭环

页面 ID agentic-rsi。
建议时长 1.0 分钟。
论文出处 [第 1 节引言首段](https://arxiv.org/html/2608.07645v1#S1)。

口播

自改进 AI 的想法可以追溯到四十年前。
1987 年 Schmidhuber 提出通过元学习递归改写自身的学习系统。
2003 年到 2007 年的哥德尔机给出严格版本，只有当收益可证明时才执行自指修改。
大语言模型与 coding agent 让这个闭环在经验层面第一次跑得通。
今天的做法把可证明收益放宽为可测量收益。
agent 编辑自身的提示、工具与控制逻辑，在留出任务上评估，性能提升就接受这次改动，否则丢弃。
这就是屏幕下方的评估、诊断、修改、再评估四步闭环。

转场

这个闭环已经被反复优化过，接下来看优化集中在哪里。

## 第 2 页 开放式演化建立档案库搜索

页面 ID rsi-progress。
建议时长 1.0 分钟。
论文出处 [第 1 节](https://arxiv.org/html/2608.07645v1#S1) 与 [第 6 节相关工作](https://arxiv.org/html/2608.07645v1#S6)。

口播

三项工作定义了当前的技术路线。
SICA 证明一个具备文件编辑工具的 coding agent 可以自主重构自己的代码库并提升基准表现。
DGM 把这个过程重构为开放式演化，维护一个不断扩展的变体档案库，每一轮从档案库里采样一个父代来启动下一次自主修改。
HGM 进一步把档案库维护当作固定预算下的树搜索，用分支后代的表现来决定下一步是评估还是扩展。
这条路线的进步几乎都发生在档案库怎么存、下一个采样谁这两件事上。
自主修改本身的输入始终是单个 agent 在单个任务上的一条失败轨迹。

转场

于是档案库被当成排行榜使用，里面更丰富的信息没有进入修改环节。

## 第 3 页 档案库轨迹驱动自主修改

页面 ID self-modification-gap。
建议时长 1.5 分钟。
论文出处 [第 1 节第三段](https://arxiv.org/html/2608.07645v1#S1)。

口播

左边是档案库今天承担的角色。
谱系树存下所有生成过的 coding agent 和它们的评估轨迹，π 采样据此分配评估与扩展预算，分支后验决定优先探索哪些节点。
这些信号全部服务于选谁，而不进入改什么。
右边是我们主张档案库还能提供的信号。
同一个 agent 在多个任务上的失败模式可以汇总，反复出现的缺陷与一次性的偶然失误因此被区分开。
其他谱系在同一任务上的成功轨迹可以作为参照，支持定向的能力迁移。
MGM 的核心机制就在这一行。
我们把档案库里已经存在的轨迹转化为 Φ 自主修改的比较证据。
这些轨迹来自例行评估，因此不需要新增任何任务评估，token 开销也保持同一量级。

转场

要说清怎么替换证据，先把基线的搜索骨架摆出来。

## 第 4 页 MGM 升级 HGM 扩展证据

页面 ID hgm-search-skeleton。
建议时长 1.0 分钟。
论文出处 [第 2 节预备知识](https://arxiv.org/html/2608.07645v1#S2)，式 1 至式 7。

口播

我们沿用一套遗传学的记号。
coding agent 的提示、工具与控制逻辑是基因型，它在任务上的轨迹与成败结果是可观测的表型，期望效用就是任务分布上的成功率。
每个档案库节点记录已评估任务集合与失败集合，分支节点再聚合全部后代的成败统计。
HGM 对节点级与分支级成功率维护 Beta 后验，用 Thompson 采样在一次 φ 评估和一次 Φ 扩展之间做选择。
自主修改写成 a 撇等于 Φ 作用在 agent 和证据 E 上。
MGM 完整保留档案库结构与 π 采样策略，只重写证据 E 的构造方式。
把单轨迹证据升级为跨任务与跨谱系的比较证据。

转场

下一页用一张图给出完整的循环。

## 第 5 页 MGM 比较演化闭环

页面 ID method-overview。
建议时长 1.5 分钟。
论文出处 [图 1](https://arxiv.org/html/2608.07645v1#S1.F1)。

口播

这是 MGM 的总览图。
中间是档案库，它维护一棵谱系树，每个节点保存自己的源码作为基因型，保存评估结果作为表型。
每一轮由 π 采样决定动作，并从档案库中取出这次动作所需的资源。
φ 评估让选中的 agent 去跑还没做过的任务，把轨迹和结果写回档案库。
Φ 扩展执行自主修改，右侧三个分支就是三种算子。
克隆突变基于目标任务上的一条失败轨迹。
反应规范突变基于同一个 agent 在若干参考任务上的多条轨迹。
跨谱系杂交基于另一谱系的参考 agent 在同一任务上的轨迹。
三种算子共用同一套评估记录，因此比较证据完全来自例行评估的副产品。

转场

先解释这两类比较为什么在诊断上更有价值。

## 第 6 页 比较轨迹定位可修复缺陷

页面 ID comparative-signals。
建议时长 1.5 分钟。
论文出处 [第 1 节第三段](https://arxiv.org/html/2608.07645v1#S1) 与 [第 3.1 节](https://arxiv.org/html/2608.07645v1#S3.SS1)。

口播

第一类比较固定基因型，改变环境。
一个 agent 在多个任务上的成败模式构成反应规范，这个概念在 1909 年由 Woltereck 提出，描述同一基因型在不同环境下的表现轮廓。
如果同一个失败模式在多个任务上反复出现，它更可能是框架层面的真实缺陷，而不是某个任务的偶然情况。
第二类比较固定环境，改变基因型。
多个 agent 尝试同一个任务时，它们轨迹之间的差异揭示了可迁移的行为特征。
把这种对比交给编辑者，可以实现跨谱系的定向能力迁移，同时减少重复探索。
这正是孟德尔遗传学的思路，通过受控比较分离可继承的效应。
我们把证据的作用范围直接映射为三种算子。

转场

下面给出三种算子的可用条件与证据集合。

## 第 7 页 三种算子组织比较证据

页面 ID evolution-operators。
建议时长 2.0 分钟。
论文出处 [第 3.1 节](https://arxiv.org/html/2608.07645v1#S3.SS1)，式 8 至式 15。

口播

克隆突变是基线算子。
只要选中的 agent 至少有一个失败任务就可用，证据是这一条失败轨迹和它的结果。
它保留 DGM 与 HGM 的自主修改行为，保证档案库很小的时候搜索仍能推进。
反应规范突变要求同一个 agent 已经在至少 m 个不同任务上被评估过，并且其中至少有一次失败。
证据是目标任务与参考任务上的两条轨迹，参考任务优先选同样失败的那一条。
编辑者被要求先找出两条轨迹共有的行为模式，再实现一处一般化的改进。
跨谱系杂交要求两个谱系尝试过同一个任务，并且这个任务没有被两者同时解决。
证据是目标 agent 与参考 agent 在这同一任务上的两条轨迹。
这里需要强调一点，杂交是一个诊断过程。
MGM 不把参考 agent 的源文件拼接过来。
我们要求目标 agent 自己从参考轨迹里提取可迁移的行为特征，再按自己的代码结构实现出来。
这样失败的谱系继承到的是一处真实改进，而不是针对单个任务的补丁。
三种算子最终执行同一个接口，差别只在目标 agent 与证据的选择。

转场

接下来是这些证据在预算内如何被稳定制造出来。

## 第 8 页 轨迹复用实现预算内扩展

页面 ID sampling-and-selection。
建议时长 1.0 分钟。
论文出处 [第 3.2 节](https://arxiv.org/html/2608.07645v1#S3.SS2) 与 [附录 A.1 算法 1](https://arxiv.org/html/2608.07645v1#A1)。

口播

左边是失败任务池。
它收录任何一个已评估 agent 暴露过失败的任务。
为某个 agent 挑选新任务时，池内任务获得一个大于一的权重，池外任务权重为一。
这个设计有两个作用。
每次 φ 评估更可能落在已知能暴露弱点的任务上，诊断价值更高。
同时它刻意制造了跨谱系的任务重叠，而跨谱系杂交恰好需要共享任务，于是可比较的对照在不额外花预算的情况下变多了。
右边是算子选择。
当 π 决定对某个父代做扩展时，MGM 先根据档案库里现有的证据构造合格算子集，再按可配置权重在其中采样。
如果没有任何算子合格，这次扩展被跳过，预算改为一次评估。
需要强调的是失败任务池不是新的评估集合，它只改变任务采样的权重。

转场

这套机制跑完之后，档案库长成什么样。

## 第 10 页 35B 开源模型达到前沿性能

页面 ID frontier-performance。
建议时长 1.5 分钟。
论文出处 [图 2](https://arxiv.org/html/2608.07645v1#S5.F2) 与 [第 5.1 节](https://arxiv.org/html/2608.07645v1#S5.SS1)。

口播

横轴是模型参数量，纯对数刻度，纵轴是 Polyglot 准确率。
我们以 Qwen3.6-35B-A3B 为基座，全程不改动任何模型权重，只演化 agent 框架。

这个结果说明性能提升被编码在框架里，而且可以被更强的基座进一步放大。

## 第 11 页 MGM 在两项基准持续领先 HGM

页面 ID benchmark-gains。
建议时长 1.5 分钟。
论文出处 [表 1](https://arxiv.org/html/2608.07645v1#S5.T1) 与 [图 6](https://arxiv.org/html/2608.07645v1#S5.F6)。

口播

这是与 HGM 的受控比较。
两种方法从完全相同的初始 agent 出发，使用相同基座，各消耗 200 次 φ 评估与 24 次 Φ 扩展。
在 SWE-bench Verified 的 60 题子集上，初始准确率 68.3%，HGM 提升到 73.3%，MGM 提升到 78.3%。
在 Polyglot 的 60 题子集上，初始 50.8%，HGM 提升到 77.9%，MGM 提升到 93.2%。
两项基准平均，MGM 带来 26.2 个百分点的绝对提升，相对提升 44.0%，HGM 的对应数字是 16.0 个百分点与 26.8%。
最下面一行是墙钟时间，两种方法在 8 卡 H100 上耗时基本相同，Polyglot 上 MGM 还略快一些。
我们另外统计了每一步的 token 消耗，HGM 与 MGM 所有算子的开销都在同一量级。
评估次数、扩展次数、时间与 token 都被控住，所以这个差距只能归因于证据质量。

转场

演化出来的改进如果只在训练基准上成立，价值有限，所以我们做了两组迁移实验。

## 第 12 页 跨基准迁移保留 40.1% 增益

页面 ID cross-benchmark-generalization。
建议时长 1.0 分钟。
论文出处 [表 2](https://arxiv.org/html/2608.07645v1#S5.T2) 与 [第 5.2 节](https://arxiv.org/html/2608.07645v1#S5.SS2)。

口播

第一组实验冻结在 Polyglot 上演化好的框架，零样本评估到两个留出基准上。
SWE-bench Pro 提供更难的代码仓库级设定，需要理解大型代码库、定位相关文件并给出稳健补丁。
SWE-bench Multilingual 覆盖多种编程语言的仓库，考察框架的语言通用性。
初始框架在两者上分别是 16.7% 与 41.7%。
HGM 演化的框架在 SWE-bench Pro 上掉到 13.3%，在 Multilingual 上只涨到 43.3%，平均下降 0.9 个百分点。
MGM 演化的框架在两者上分别达到 26.7% 与 55.0%，平均提升 11.7 个百分点，相对提升 40.1%。
这说明 MGM 学到的改动没有过拟合到 Polyglot 的失败模式上。

转场

第二组实验换掉的不是基准，而是基座模型。

## 第 13 页 Qwen 演化框架迁移至 DeepSeek

页面 ID cross-model-generalization。
建议时长 1.0 分钟。
论文出处 [表 3](https://arxiv.org/html/2608.07645v1#S5.T3)。

口播

这里的框架在 SWE-bench Verified 的 60 题子集上用 Qwen3.6-35B-A3B 演化，然后被冻结，只替换推理基座。
换成 DeepSeek-V4-Flash，初始框架 50.0%，HGM 到 60.0%，MGM 到 66.7%。
换成 DeepSeek-V4-Pro，初始框架 45.0%，HGM 到 70.0%，MGM 到 75.0%。
两个迁移基座平均，MGM 达到 70.8%，HGM 为 65.0%，初始框架为 47.5%。
两种方法都能迁移，而 MGM 的迁移更强也更稳定。
这条协议隔离了一个关键问题，改进究竟写在框架里，还是只适配了原来那个基座的特性。
结果支持前者。
把两组迁移放在一起看，可以得到一条实用路径。
在小基准和便宜基座上演化框架，再迁移到更强的模型上使用。

## 第 14 页 加性景观刻画位点修复

页面 ID additive-landscape。
建议时长 1.0 分钟。
论文出处 [第 4.1 节](https://arxiv.org/html/2608.07645v1#S4.SS1) 与 [图 3](https://arxiv.org/html/2608.07645v1#S4.F3)。

口播

为了在实现细节之外隔离方法本身的贡献，我们构造了一个可控的替身模型。
每个 agent 的基因型是长度 L 的二元向量，每一位对应一项最小的框架级能力或实现选择。
固定一个理想最优基因型，与它的汉明距离度量当前 agent 还有多少优化空间，距离为零当且仅当达到最优。
基因型不可直接观测。
每个任务考察其中一个大小为 k 的位点子集，只有被考察的位点全部正确，任务才算解决。
于是编辑距离为 d 的 agent，单题成功概率是 L 减 d 除以 L 的 k 次方。
这个设定对应真实编码任务的一个事实，一道题往往要求定位、推理、编辑与验证同时正确。

转场

在这个模型里，比较证据的作用可以被精确写出来。

## 第 15 页 比较证据提高有效修复概率

页面 ID diagnostic-compression。
建议时长 1.0 分钟。
论文出处 [第 4.2 节与命题 1](https://arxiv.org/html/2608.07645v1#S4.SS2) 与 [附录 B.1](https://arxiv.org/html/2608.07645v1#A2)。

口播

编辑者看不到隐藏的错误位点。
它只能根据证据 E 构造一个候选位点集合，然后在其中尝试修复，命中真错配位点时以概率 s 修好。
所以有效修复概率等于 s 乘以候选集中真错配位点的比例。
克隆突变只观测一条失败轨迹，它能推出的信息仅仅是这道题考察的位点里至少有一个是错的，候选集就是整个考察集合。
反应规范突变比较同一基因型的多条轨迹，当两次失败共享一个框架级缺陷时，候选集压缩为两个考察集合的交集，期望上严格更小。
跨谱系杂交比较同一任务下的不同基因型，参考 agent 的成功轨迹起到对照作用，把与因果无关的位点过滤掉。
命题 1 因此成立，两种比较算子的有效修复概率严格高于克隆突变，完整推导在附录 B.1。
直观地说，比较证据没有让编辑者本身变强，它缩小并净化了编辑者要搜索的缺陷集合。
我们用一个修复概率比 ρ 把这个优势参数化，ρ 等于一表示比较证据不带来任何诊断收益。

转场

## 第 17 页 比较证据驱动可复用进化

页面 ID closing。
建议时长 1.0 分钟。
论文出处 [第 7 节结论](https://arxiv.org/html/2608.07645v1#S7) 与局限性。

口播

孟德尔-哥德尔机把档案库从搜索记忆升级为自主修改的证据库。
三点结论。
第一，证据复用。
跨任务与跨谱系的轨迹直接进入 Φ，全部来自例行评估，不增加任务评估，token 开销保持同一量级。
第二，性能与迁移。
同预算下 MGM 在两项代码基准上稳定优于 HGM，演化出的框架跨基准、跨基座模型都保留增益。
第三，理论解释。
比较证据压缩候选缺陷集合，提高有效修复概率，因此更快逼近最优。
也说明边界。
MGM 依赖历史，档案库很小、任务重叠稀疏或者信息量足够的失败还没出现时，它的行为会接近单轨迹基线。
更好的证据也不保证更好的编辑，实际改动仍由基于大模型的编辑者产出。

## 预备问答

关于两种比较算子各自的贡献。
论文第 5.3 节在 Polyglot 的 60 题子集上做了消融，同预算、同初始 agent，去掉反应规范突变或去掉跨谱系杂交都带来明显下降，其中跨谱系杂交的影响更大，我们的解释是它把有用的演化信息在迭代之间保留并复用。
消融变体的训练时长相当，因此下降来自算子而不是算力差异。

关于增益是否来自更多的 token。
论文图 6 给出 HGM 与 MGM 所有评估与扩展操作的 token 分布，处于同一量级。

关于杂交是否等于代码拼接。
不做拼接。
目标 agent 从参考轨迹中提取可迁移的行为特征，再按自己的代码结构重新实现，论文第 3.1 节对此有明确说明。

关于杂交时谁被编辑。
共享任务上只有一方解决时，失败方被编辑，成功方作为参考；两方都失败时，效用更高的谱系作为主谱系，规则在附录 A.2。

关于安全性。
自主修改与评估全部运行在隔离容器中，无网络访问，宿主文件系统只读挂载，沿用此前档案库式自改进工作的安全协议，见论文伦理讨论部分。

关于种子与方差。
仿真结果跨多个蒙特卡洛种子报告均值与 95% 置信区间。
真实演化实验成本高，独立种子数量有限，论文局限性部分对此有说明。
